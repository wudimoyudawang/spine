1核心设计决策

D1 · 统一事项模型（one record, many views）

不按「习惯表 / 待办表 / 计划表」分家。所有事都是同一种记录 Item，靠标签区分：

形态 type —— 决定怎么完成：习惯 = 重复打卡，待办 = 勾选，计划 = 推进进度

领域 domain —— 决定归属哪个空间：健身 / 学习 / 工作 / 个人生活

跨度 horizon —— 决定怎么排期与提醒：短期 / 长期

状态 status —— 决定出现在哪个视图：收件箱 / 待办 / 进行中 / 已完成

为什么这样设计：你的原始需求里「健身计划」同时是习惯（每周三练）、待办（买蛋白粉）、长期目标（半年增肌 5kg）。如果按形态建三张表，它就要被录三遍。

D2 · 领域是主组织轴

你说的「健身单独一个页面、学习单独一个页面」→ 落实为 领域空间。每个空间页混装该领域下全部形态的事项，不做二级切分。领域可自定义增删，默认给 4 个：健身 学习 工作 个人生活。

D3 · 形态是交互轴，不是导航轴

形态不在侧边栏出现，而是决定这条事项在列表里长什么样、点什么按钮：习惯行右侧是打卡按钮，待办行是勾选框，计划行是进度条。

D4 · 「短期 / 长期」是属性，不是模块

不单独开「短期计划页」和「长期计划页」。跨度只作为筛选条件和排期依据（长期 → 季度 / 年度视图，短期 → 周 / 月视图）。这是对你原始需求的一处修正建议。

D5 · Local-first，云为可选

  • 不登录：数据全在本地（浏览器 IndexedDB / SQLite），功能完整可用，不是阉割版
  • 登录后：开启多端同步，本地数据与云端合并
  • 因此：v0.1 完全不碰账号和同步，这是后续独立的一次大迭代

2信息架构

今日 (Today) ← 主入口。跨领域聚合：今天该打卡的习惯 + 今天到期的待办 + 进行中的计划节点 收件箱 (Inbox) ← 3 秒速记落点，未分类事项暂存区 领域空间 ×N ← 健身 / 学习 / 工作 / 个人生活（可增删），页内混装全部形态 └─ 空间内筛选：全部 / 习惯 / 待办 / 计划 / 已完成 日历视图 ← v0.2 统计与复盘 ← v0.3 设置 ← 账号、同步、数据导出、领域管理

导航优先级：今日 > 领域空间 > 收件箱。打开应用默认落在「今日」。

3MVP（v0.1）范围

目标

任何事 3 秒记下来；今天该做什么，一屏看完。

做什么（P0，全部必须）

#能力说明
P0-1统一收集全局速记入口，一句话录入，先落进收件箱
P0-2事项属性形态 / 领域 / 跨度 / 日期 / 备注，可后补
P0-3今日视图自动聚合今天该做的事，支持勾选完成与打卡
P0-4领域空间页4 个默认空间，展示该领域全部事项
P0-5本地持久化不登录也能完整使用，刷新 / 关闭不丢数据
P0-6数据导出一键导出 JSON，避免数据被锁死

明确不做（v0.1 非目标）

  • 账号体系与云同步 → v0.2
  • 多用户 / 朋友共享 → v0.2
  • 统计图表、连续天数、热力图 → v0.3
  • 日历视图、甘特图、长期计划拆解 → v0.2
  • 消息提醒推送 → 技术风险待验证，见 R2
  • 原生 App / 微信小程序 → 见第二轮问题 1
  • 附件、图片、富文本
范围原则：7 个模块一次全做是本项目最大的风险。MVP 只交付「收集 + 今日」两个页面，先把「信息不散」这件事解决掉，其余模块都是在这条管道上加视图。

5需要你确认的第二轮问题

按重要性排序，前 4 个会直接影响技术选型，请优先回答。

#问题我的建议
1平台形态：做响应式 Web + PWA（手机加到桌面、电脑用浏览器、NAS 部署一份）？还是必须原生 App / 微信小程序？推荐 Web + PWA。一套代码覆盖三端，NAS 部署最自然，符合你「自己的服务器」思路
2速记要不要自然语言解析？例如输入「明天下午3点 交周报 #工作」自动识别日期与领域建议 v0.2 做。这是体验分水岭，但属于「智能增强」，不该挡在 MVP 前面
3「今日」的定义：只含今天到期？还是也含逾期未完成 + 今天该打卡的习惯？建议三者都要，逾期置顶。否则「今天」会漏事，违背核心痛点
4首次登录时本地已有数据怎么处理：自动上传合并 / 让用户二选一 / 询问后合并？建议「询问 + 默认合并 + 合并前自动备份」，这是 local-first 最容易丢数据的地方
5习惯重复规则支持到什么程度：每天 / 每周几 / 每月某日 / 每 N 天 / 自定义？建议先支持前四种，自定义后置
6长期计划怎么推进：里程碑 + 进度条，还是拆成子待办？建议里程碑 + 进度条，子任务结构对个人使用偏重
7要不要提醒？注意 iOS 浏览器对 PWA 通知限制很大建议 v0.1 不做提醒，靠「打开即见今日」。若必须要，改用邮件或微信通知，第二期再评估
8朋友使用：只要各自独立账号，还是需要互相看到计划？独立账号简单一个量级，强烈建议先只做这个
