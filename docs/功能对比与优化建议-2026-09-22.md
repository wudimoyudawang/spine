# 功能对比与优化建议（2026-09-22）

> 对标对象：滴答清单 / TickTick、Todoist、flomo、Daylio、Habitica、时光序、Super Productivity。
> 数据来源：ticktick.com 官网功能页（2026-09-22 抓取）+ 本仓库 [research-02](archive/research-02-竞品调研与功能聚合边界.md)（2026-09-18）。
> 本文只做对比和建议，**不改变已定的任何边界**（模块冻结 5-6 个、第 5 步之前不碰服务器、零广告零付费墙）。

---

## 0. 一句话结论

**不缺功能，缺三样「基本功」：重复待办、全局搜索、快速记认得日期。**
这三样都是 TickTick 的骨架功能，都不新增模块、都纯本地可做、都直接服务「3 秒记下来 / 一眼看到今天」。
市面上其余的热门功能（番茄钟、看板、标签、游戏化、AI），按本项目自己的判据，**一个都不该进**。

## 2. 建议新增（按优先级）

### ① 重复待办（优先级：高）

**现状**：到期日是一次性的。「每周五交周报」「每月 5 号交房租」这类事，做完一次就得手动重建一条。

**为什么值得**：周期性事务是待办工具的半壁江山（TickTick 把「重复提醒」列在提醒功能第一条）。
数据上只是给 Item 加一个 `repeat` 字段 + 完成后把到期日推到下一期，**不新增模块、不新增视图**。

**过判据**（research-02 §7.1）：进今日/领域视图 ✅、与待办同一决策 ✅、录入一句话可带（「每周交周报」）✅、够用即可 ✅。

**成本**：中。涉及「完成后推进到期日」的规则（每周/每月/每年），以及逾期和重复的叠加情况。

### ② 全局搜索（优先级：高）

**现状**：完全没有。现在数据少感觉不到，等记了两三百条之后，「我明明记过那条」会变成真痛点——
而且本项目没有同步、没有服务器，搜不到就真找不回来。

**为什么值得**：成本收益比最好的一项。数据全在本地，遍历 `ITEMS / NOTES / LOGS / DOMAINS` 就是一个搜索框的事。

**成本**：低。

### ③ 快速记识别日期（优先级：高）

**现状**：快速记能认出「32 午餐」「5 公里」「提到卡路里」，但「明天交周报」认不出「明天」，
日期得开编辑弹窗去填——这一下就把「3 秒记下来」拉长成十几秒。

**为什么值得**：顺着**现有规则引擎**加一组日期规则（今天/明天/后天/下周X/X号/X月X日），不新增模块。
TickTick 把「智能识别时间」列为核心功能第一条，flomo 的成功也建立在「不用想格式」上。

**成本**：中低。

### ④ 自动备份（优先级：高，但可以排在上线前）

**现状**：只有手动「存成文件」。research-02 的防守策略第 3 条写明：
**「上线前必须有自动备份 + 一键导出」（反时光序数据丢失教训）**。

**做法**：本地保留最近 N 份快照（比如每天一份、留 7 份），设置页给个「恢复到某一天」。

**成本**：低。

### ⑤ 习惯频率从文案变成规则（优先级：中）

**现状**：习惯的「每周 4 次」只是说明文字；连续天数按**日历日**口径算，
跳过周末就断——这对「工作日才做」的习惯是不公平的惩罚。

**为什么值得**：research-02 把它列在「追平领域」（该做但不追求顶尖）。
**成本**：中。涉及 streak 口径重算，动的是已上线的东西，要小心。

## 4. 明确不做（这张清单和功能清单一样重要）

| 不做 | 理由 |
|---|---|
| **番茄专注** | 新模块。判据 1 不过：专注时长进不了今日/领域闭环。Forest / TickTick 已是 99 分，本项目做到 80 分没有意义 |
| **看板 / 时间线视图** | 纯视图花样，不服务「一眼看到今天」。视图数每加一个，维护债加一份 |
| **标签 / 过滤器** | 领域已经是主组织轴。加标签等于第二套分类，是 D2 的反面 |
| **位置提醒** | 需要常驻定位权限，和一个「安静的本机工具」气质相反 |
| **附件 / 图片 / 录音** | 本地存储会膨胀，导出文件会大到没法用剪贴板传 |
| **游戏化** | Habitica 那套。和「安静地记」的气质相反，而且连续天数本身已经是反馈 |
| **主题商店** | 四象限配色已可自定义，够用 |
| **AI 语义识别** | 已定：用规则表。规则可解释、可自己改，AI 不可 |
| **多端同步 / 账号** | 第 5 步。先做后端 = 在没有真实使用数据的情况下设计同步协议 |

**等 App 壳稳定之后再说**（不是不做，是排不到现在）：

- **提醒 / 本地通知**——待办工具最核心的缺口，但 H5 没有通知能力，App 壳才刚能出包。
  本地通知不需要服务器，值得排第 5 步前。
- **桌面小组件 / 语音录入 / 全局快捷键**——同样是壳的能力。

---

## 5. 如果只做三件

1. **重复待办**——周期性事务是日常的一半，现在每次都得手动重建。
2. **全局搜索**——成本最低，越早做越便宜。
3. **快速记认日期**——直接把「3 秒记下来」从口号变成事实。

三件都不新增模块、不碰服务器、不加第五种颜色。
