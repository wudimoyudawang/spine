# 书脊 · Spine

**个人计划中枢** —— 一个本地优先（local-first）的个人管理系统。

习惯打卡、待办、长短期计划、记账、热量与体重、随心记、复盘，全部收在一处。
**未登录也能完整使用全部功能**，登录只是为了多端同步（第 5 步的事，现在没做）。

## 现在能用了

**应用本身已经完整**，功能都在 `app/` 里跑通了。安装包在 `release/spine.apk`。

- 数据**全部存在手机本机**，不联网、不要账号。关掉再打开，记的东西还在。

只在电脑上看看它长什么样：打开 [`app/`](app/) 跑 `npm run dev:h5`，
或者看那版定稿的单文件原型 [`prototype/index.html`](prototype/index.html)（零依赖，双击即开）。

## 界面上长什么样

底栏四项 **今日 / 收集 / 随心记 / 复盘**，中间一颗**加号**。
页头右上角一颗**齿轮**，点进「空间」（往下滑就是设置）。

加号弹出一个面板，面板底部有切换器，在**记一笔**和**记账**之间切：

| 入口 | 职责 |
|---|---|
| **记一笔** | 写什么都行，规则自己判：数字开头记成支出、提到卡路里记成热量、提到公斤记成体重、其余记成待办。也可以手选一个模式，右侧「自定义」里是**空间里所有能记的东西** |
| **记账** | 先挑品类、再填金额。**品类是必选的** —— 记账的价值就在分类上，随手记错分类到月底会裂成两根柱子 |

| 页面 | 职责 |
|---|---|
| **今日** | 跨领域聚合：记账行 → 逾期 → 待办（可切「已完成」）→ 习惯打卡 → 长期计划进度 → 今天记下的 |
| **收集** | 收件箱。只解决「先记下来别丢」，归类以后补 |
| **随心记** | 零字段文本框，无统计、无红点、无连续天数。默认**不进**任何聚合与复盘 |
| **复盘** | 本周 / 本月 / 自定义区间，每行趋势都是**本期对上一期** |
| **空间** | 领域卡片（健身/学习/工作/个人 + 你自己建的）+ **记账**（固定卡，不可改删）。鼠标往下滑就是设置 |

## 关于签名（升级会不会丢数据）

安装包用一份**固定的发布签名**签的，所以：

- **平时升级**：直接覆盖安装，**数据全在**。
- **唯一要卸载重装的情况**：换壳（从现在的壳换成 DCloud 官方壳）或改应用包名。
  那一次之前，记得先去空间页**存成文件**导一份。

签名是**两个文件**，都在 `shell/` 下，两个都不进仓库
（根 `.gitignore` 拦了 `*.jks`，也拦了 `keystore.properties`）：

```
shell/spine-release.jks      keystore 本体
shell/keystore.properties    别名和口令，指向上面那个文件
```

```
alias    : spine
storepass / keypass : 见 shell/keystore.properties
有效期   : 36500 天（100 年）
```

**这两个文件别丢。** 丢了就打不出能覆盖安装的包了，只能卸载重装一次（数据一起没）。
备份还在仓库外的 `C:\workbuddy\.toolchains\` 下有一份。
应用包名是 `cn.spine.app`，它也决定了能不能覆盖安装，改它同样要卸载重装。

## 核心设计决策

这五条决定了整个数据结构和交互，后面所有功能都建在它们之上。

| # | 决策 | 含义 |
|---|---|---|
| D1 | **统一事项模型** | 所有事都是同一种记录 `Item`，靠四项标签区分：**形态**（习惯/待办/计划）、**领域**（健身/学习/工作/个人…）、**跨度**（短期/长期）、**状态** |
| D2 | **领域是主组织轴** | 健身页、学习页各自**混装**该领域全部内容，不需要在页面之间跳转 |
| D3 | **形态是交互轴，不进导航** | 习惯行是打卡按钮，待办行是勾选框，计划行是进度条 —— 它决定「怎么完成」，不决定「在哪儿」 |
| D4 | **跨度是属性，不是页面** | 「短期 / 长期」只影响怎么排期和提醒。开成两个页面会让你有大量事项纠结该放哪边 |
| D5 | **Local-first** | 本地存储是主体，云端是可选增强。核心层永远不依赖网络、不依赖账号、不依赖任何外部服务 |

两条由此推出的推论，值得单独说：

- **「记账 / 热量 / 体重 / 打卡」不是四个功能，是同一种东西** —— 带数值的按时间记录。
  它们在数据里共用一套结构，靠 `kind` 和「记录项定义」区分输入界面。
  所以将来想加「喝水量」「睡眠时长」「阅读页数」「模拟考试分数」，**不用改数据结构**。
- **领域是用户自己长的，不是写死的四个。** 每个领域天生带三样通用容器（习惯 / 待办 / 长期目标），
  可以自由新建、改名、删除、置顶。领域里还能自己定义「记录项」——
  纯文字（记过程和感受）或数值（看趋势），名称和单位你自己填。

还有一条验收标准：**任何东西 3 秒内能记下来；今天该做什么，一眼看到。**
新增任何功能，「记一笔」的中位操作步数超过 3 步就算不合格。

## 工程结构

```
prototype/index.html   行为参照物。重构前定稿的单文件原型（零依赖，双击即开）
app/                   uni-app + Vue3 工程 —— 当前施工落点，页面都在这儿
shell/                 Android 壳：把 app 的 H5 产物包成 APK
  ├ make-apk.cjs       一键出包
  ├ android/           Capacitor 生成的 Android 工程（Gradle + SDK 34）
  ├ spine-release.jks  \ 签名，**不进仓库**，换机器要自己带
  └ keystore.properties/  （根 .gitignore 拦着这两个）
release/spine.apk      打包好的安装包
docs/                  设计文档
```

`prototype/` 和 `app/` 是**两套独立的东西**，不是一份代码的两份拷贝：
原型是定稿过的行为基准，`app/` 是对它的重新实现。原型**不再改**。

## 怎么跑起来

**开发预览**（浏览器里看，改一行立刻刷）：

```
cd app
npm install
npm run dev:h5
```

**自己打一个 APK**：

```
cd shell
npm install
node make-apk.cjs
```

`make-apk.cjs` 会依次做四件事：构建 `app/` 的 H5 产物 → 搬进壳的 `www/` →
把原生适配脚本拼进 `index.html` → Gradle 打 release 包，产物拷到 `release/spine.apk`。

### 换一台机器打包

仓库里**没有** JDK、Android SDK、keystore —— 这三样是本机的，换机器要自己带。
步骤：

1. **装 JDK 17**（任意发行版）。
2. **装 Android SDK**，只要三块：`platform-tools`、`platforms;android-34`、`build-tools;34.0.0`。
   有 Android Studio 的话它会自己装好。
3. **把 keystore 带过去**：拷 `shell/spine-release.jks` 和 `shell/keystore.properties` 两个文件。
   （这一步别省。没有它也能出包，但会退回 Gradle 的 debug 签名 ——
   **签名和现在这个包不一样，装上去必须先把旧版卸掉，数据一起没**。）
4. **把 JDK 和 SDK 的位置告诉脚本**，二选一：

   ```
   set SPINE_JDK=D:\jdk-17
   set SPINE_ANDROID_SDK=D:\Android\Sdk
   ```

   （PowerShell 里用 `$env:SPINE_JDK="D:\jdk-17"`。）
   不设的话会依次找 `JAVA_HOME` / `ANDROID_HOME` / `ANDROID_SDK_ROOT`。

5. `cd shell && npm install && node make-apk.cjs`

**慢的话**，先把这两处镜像确认在位（仓库里已经配好了，正常不用动）：

| 什么 | 用哪儿的源 | 配在哪儿 |
|---|---|---|
| Gradle 自己（122MB） | 腾讯镜像，且用 `-bin` 而不是 `-all` | `shell/android/gradle/wrapper/gradle-wrapper.properties` |
| AGP / androidx 依赖 | 阿里云，官方源留作兜底 | `shell/android/build.gradle` |

> 用 `-bin` 而不是 `-all` 不只是省 60MB：解压时要逐个创建文件，
> `-all` 的文件数是 `-bin` 的两倍多，在文件操作慢的机器上差得很明显。

签名哪里读、字段怎么写，见 [`shell/keystore.properties.example`](shell/keystore.properties.example)。

### 如果 Gradle 卡住不动

先量一下文件操作速度 —— **别先怀疑 Gradle**：

```js
// node 里跑，先建一个临时目录
const fs=require('fs'), t=Date.now()
for(let i=0;i<400;i++) fs.writeFileSync('_bench/f'+i+'.txt','x')
console.log(Date.now()-t, 'ms')
```

400 个空文件正常应该在 **1 秒内**。如果像这台机器一样要 **十几秒**，
那就是杀软/EDR 的实时扫描在拦每一次文件创建，Gradle 要建上万个文件，必然卡死。

实测对比（同一块盘）：

| 位置 | 写 400 个小文件 | 删 400 个小文件 |
|---|---|---|
| `C:\workbuddy` | 16.2 秒 | 34.2 秒（12 个/秒） |
| 系统临时目录 | 0.5 秒 | 0.8 秒（471 个/秒） |

**同一块盘慢 40 倍**，说明拦的是目录不是磁盘。处理办法：
给项目目录加杀软白名单，或者干脆换台机器打。

> **为什么是 Capacitor 壳而不是 HBuilderX 的官方壳？**
> 两条路的**前端代码完全一样**，区别只在最后一步由谁把代码装进 APK。
> 官方壳要 HBuilderX（GUI）加一个绑账号的 Appkey，那一步得人工点；
> Capacitor 是纯命令行，能一条命令重打。
> `app/` 的 App 资源包（`npm run build:app`）也随时能出，将来想换官方壳不用改页面代码。

## 技术栈

| 层 | 选型 | 状态 |
|---|---|---|
| 前端 | **uni-app + Vue3 + Vite**（一套代码，可编译到 H5 / App / 小程序） | 已跑通 |
| 前端存储 | 本机 `uni.setStorageSync`，接口只有 `snapshot()` / `restore()` 两个函数 | 已落本机 |
| Android 壳 | Capacitor 6 + Gradle（Android SDK 34） | 壳就绪，出包待正常机器 |
| 后端 / 数据库 / 部署 | Python + FastAPI + SQLModel + SQLite + Docker | **第 5 步才做** |

**存储层刻意做薄**：全部接口就是 `snapshot()` / `restore()` 两个函数，
调度也只有「改了就每 2 秒兜一次 + 页面隐藏/卸载时各一次」这一条路。
不做「每个改数据的地方都记得调一次存」—— 那种写法迟早漏一处，
而漏的永远是用户刚记的那一笔。将来换 SQLite 或接后端，只改这两个函数。

**存不下时必须出声**：存满了或被禁时，设置页那行会从「已自动保存」变成实情并弹一句提示。
用户以为存住了、其实没存，是这个应用最不能出的一种错。

## 路线

五步，**每一步结束时都必须能真的打开来用**。
不按「先做完功能再能用」的顺序施工 —— 那样你会长期对着一个跑不起来的半成品。

| 步 | 目标 | 做完后能干什么 |
|---|---|---|
| **1-4** | 能记下来 → 能看清今天 → 能记住细节 → 能回头看看 | **已完成**，见上面「现在能用了」 |
| **5** | 能给朋友用 | Docker 打包 + 后端 + 账号 + 增量同步 + 开源发布 |

**第 5 步之前完全不碰服务器。** 先做后端，等于在没有任何真实使用数据的情况下设计同步协议 ——
这是这个项目里最贵的错误。
